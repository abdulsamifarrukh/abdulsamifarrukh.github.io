Telecom

SIM issuance identity verification

I built a workflow from scratch that verifies a customer's identity before a SIM card is issued. One orchestrator runs the sequence and each stage is its own service.

The stages are an identity check, a biometric check against a government API, an SMS fallback if the biometric check fails, and then provisioning resources on the SIM before it's issued. DataPower sits between the API calls and every stage publishes its status to Kafka topics.

I went with a central orchestrator instead of choreography, so the order of the stages and the fallback rule live in one service.

Requests are idempotent. If an identity request is retried while the first one is pending or already successful, Kafka doesn't process it again and the caller gets the status of the existing request.

An audit service logs each step for governance and compliance. When the flow finishes, a Workato recipe posts a message to a Slack channel.

Built with Java APIs, IBM DataPower, Kafka, PostgreSQL and Workato.

Used-car valuation

Used-car price estimator

A small web service that estimates the market value of a used car from its year, make and model, with mileage as an optional input.

A 2015 mid-size sedan with 150,000 miles, from 1,354 comparable listings

Plain average$17,500
Mileage adjusted$14,500

It loads ~4.7 million market listings into a database, skips the rows that fail validation and counts each skip by reason. About 11% of the rows had no usable price, and ~4.2 million listings were loaded.

A search finds the comparable listings for the same year and make where the model matches. Without mileage the estimate is the plain average. With mileage I fit a line of price against mileage and read it at the mileage entered. The 150,000 mile example above came back in ~0.8 seconds.

The line is only used when at least 5 listings have a mileage and the slope is negative. Otherwise it falls back to the average and the page says why.

The app only listens on the local interface behind Nginx, which checks a token, and all SQL is parameterized. The data has mixed currencies, duplicate vehicles and stale listings, so I wrote each one down with a fix. Cleaning comes first because it would move the numbers more than the math does.

Built with Python, Flask, Gunicorn, Nginx, MariaDB and OpenAPI.

Distribution center integrations

Order, inventory, returns and shipment integrations between a retailer's internal systems and roughly 15 distribution centers and external WMS.
